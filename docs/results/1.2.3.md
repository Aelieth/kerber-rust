**Documented differences from MIT that the run shows** (each was already in the docs before the run):

- `kinit -E` with an enterprise name: MIT's KDC answers "not found", and ours finds the user
  ([deviations](../mit-deviations.md), enterprise client name).
- A cross-realm TGT whose PAC carries a LOGON_INFO that doesn't decode: MIT issues the ticket, and
  ours refuses it ([deviations](../mit-deviations.md)).
- kadmind's own TL types: a client may not set them on ours; MIT has no such types
  ([deviations](../mit-deviations.md), reserved TL types).
- MIT's test database adds a LOGON_INFO to the PAC, and a real database doesn't
  ([deviations](../mit-deviations.md), the PAC with AD data).
- A kadm5 name with no realm and no `default_realm`: MIT's `kadmind` fails the call, and ours uses the
  served realm ([interop matrix](../interop-matrix.md)).

**S4U2Self and the host.** Host admission is new in 1.2.3. For an S4U2Self request, the impersonated
local user gets MIT's entry checks, then the host's `check_as` (with `s4u2self: true`), then
`check_tgs`, which names that user, not the requesting service. So a user the host refuses can't be
impersonated. A release candidate named the service; that was fixed before the tag, and the host
contract rows above include a refused user. `[open point 3]`

1.2.3 changed no area that the earlier tables in the README cover beyond those above; those runs stand.
