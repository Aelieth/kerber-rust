# Gates — OTP preauth

The rows of the two OTP gates, which never stood in [gates.md](gates.md) (its 60 KiB is full). Both run MIT `kinit -T`
and the Rust `kinit` (copied into the container as `kinit`, so its messages carry MIT's name) cell for cell: the
first against MIT's KDC and its `otp` module, the second against the Rust KDC's.

| Gate | Oracle | Workflow | Lane | Asserts |
| --- | --- | --- | --- | --- |
| `scripts/otp-gate.sh` | MIT | `nightly:moving` | nightly | MIT 1.22.2 `krb5kdc` with its `otp` module and a stdlib RADIUS stub (`otp-radius-stub.py`, Access-Accept for one code), `[otp] DEFAULT` with `indicator = otpind`, MIT `kinit -T` then the Rust `kinit` against it, same bytes in every cell: the right code gives a TGT with ticket flags `IA`, `pa_type 141` and `fast_avail` in `klist -C`, stdout exactly `Enter OTP Token Value` plus a newline and an empty stderr, one stub Accept; a wrong code is `kinit: Preauthentication failed while getting initial credentials`, no ccache, no password read (the next stdin line is never taken), one `NEEDED_PREAUTH` and one `PREAUTH_FAILED` in the KDC log, one stub Reject; end of file at the OTP prompt with SPAKE and encrypted challenge offered is three prompts (`Password for otpuser@OTP.TEST` twice after the OTP one) and `kinit: Pre-authentication failed: Cannot read password while getting initial credentials`, the three modules' `Cannot read password` trace lines, the stub not asked; no `-T` offers no `PA-OTP-CHALLENGE`, and `kvno` of the `require_auth` service is `KDC policy rejects request` after that password TGT (`Required auth indicators not present in ticket: otpind` in the KDC log) but works after the OTP one; an `LD_PRELOAD` shim in `krb5kdc` (`otp-fast-shim.c`) reads each client's FAST request (key usage 51) and the nonce sent back (usage 45): inner padata `fastreq inner=150,149` then `133,142,150,149`, PA 142 equal to MIT's pinned bytes with the ciphertext masked, the nonce sent back the KDC's own; `[otp] DEFAULT = { timeout = 5s }` logs `preauth otp failed to initialize: Invalid integer value` and the hint has no `PA-OTP-CHALLENGE` |
| `scripts/rust-kinit-otp-gate.sh` | MIT | `nightly:moving` | nightly | The Rust KDC's OTP module through `krb5-otp-kdc` (the example embedder with a TOTP verifier; codes from the standard library, `otp-totp.py`), `[otp] totp` with `indicator = otpind`, MIT `kinit -T` then the Rust `kinit`, one user each for the right code: a TGT with `pa_type 141`, ticket flags `IA`, stdout exactly `Enter OTP Token Value` plus a newline, `kvno` of the `require_auth` service works; a wrong code is `kinit: Preauthentication failed while getting initial credentials`, no ccache, `preauth (otp) verify failure: Generic preauthentication failure`, one `NEEDED_PREAUTH` and one `PREAUTH_FAILED`, and an `LD_PRELOAD` shim in MIT `kinit` reads the Rust KDC's PA-OTP-CHALLENGE: `fastresp types=136,19,141,151,138,133,137` with MIT's hint bytes and the nonce sent back; end of file at the OTP prompt with SPAKE and encrypted challenge offered is `Cannot read password` once per mechanism, equal for both clients; no `-T` offers no `PA-OTP-CHALLENGE` and the password TGT is refused by the `require_auth` service (`Required auth indicators not present in ticket: otpind`); `[otp] totp = { timeout = 5s }` and MIT's `server` relation (`RADIUS is not implemented`) each leave the module out, log `preauth otp failed to initialize`, and the password path logs in (in the timeout case with the same bytes for both clients) |
